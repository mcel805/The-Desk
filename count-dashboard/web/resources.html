USING THE CHAT

Get a grounded chart read

  1. Choose the asset and timeframe on Count Desk.
  2. Build the count so the current chart snapshot is ready.
  3. Ask a question such as “What is the 30-minute structure, and what would invalidate that read?”
  4. Check Batty’s answer for the data source, last-bar time, and provisional labels.
CURRENT INTEGRATION

What Batty can read today

  • Count Desk: current chart context plus on-demand stored bars, drawings, level plans, and feed freshness.
  • Trading Journal: accounts, imported trade records, paper trades, reviews, and level plans can be retrieved when relevant.
  • Liquidity Lab: paper/shadow dashboard, levels, runs, trials, outcomes, and research records.

FIRSTMATE · COORDINATION LAYER

How the crew model is intended to work

Batty is the human-facing coordinator: it understands the question and active chart context, then routes technical chart interpretation to the project-scoped Cleo agent. The specialist supplies the technical read; Batty relays it with attribution and explains terms when useful.

Count Desk uses a local Codex subagent for this handoff. It is not a durable Firstmate crew task and does not provide Firstmate task IDs, follow-up/stop controls, or lifecycle tracking. Batty must say when a handoff fails instead of filling in its own chart count.

DATA & CONTROL

Clear limits, useful answers

  • Stored bars may be delayed or stale; a chart snapshot is not a live quote.
  • Structural count labels and projected paths are research aids, not validated Elliott counts.
  • Dashboard tools are read-only. They cannot change records/settings, control a broker, or route orders.
  • Relevant dashboard data and web results are sent to the selected Codex model through your ChatGPT sign-in.
  • It cannot route orders. Research replies are not trade instructions.
  • Model use follows the signed-in ChatGPT plan and its limits; it is not an OpenAI API-key connection.
