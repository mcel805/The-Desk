# Pine indicators in The Desk

Indicators → **Create Pine Script indicator** accepts self-contained native Pine v5/v6 source. Paste source or load the supplied **Market Gravity [YinYangAlgorithms]** example, select **Compile & test**, then **Add to chart** and/or **Save indicator**. Saved sources appear under **My Pine indicators** and can be exported, edited and retested, or deleted. Built-in studies remain available in the same menu. Settings, visibility, removal, layout persistence and templates work through Vela's existing indicator handles.

## Execution and conversion

The converter uses LuxAlgo's official Vela PineTS scripting adapter rather than rewriting the indicator's formulas by hand. It compiles Pine for execution in a separate worker per study and maps its plots, native lines, labels, boxes, polylines, fills and tables into Vela's chart model. The original Pine source stays attached to the indicator. Input schemas, groups, options, colors and defaults come from that source. Coinbase and Hyperliquid remain the chart-owned feeds, including secondary timeframe requests; the Pine engine does not choose an alternate venue.

A source is accepted for adding only after compilation and an execution test on the selected chart. Test indicators are removed after the test. Compilation is limited to 15 seconds and execution to 30 seconds; cancellation terminates only test workers. An installed study stops computing while hidden and resumes when shown. Source size is limited to 250 KB; the local library and each chart support six Pine studies. Strategies, Pine libraries and external Pine imports are explicitly rejected by this indicator editor.

Native Pine compatibility in PineTS is experimental. A runtime pass proves execution on the loaded data; it does **not** establish universal Pine compatibility or an exact TradingView match. Unsupported constructs must be fixed in the runtime or source and retested. Initialization/warmup, missing history, provider differences, repainting rules and rendering can affect parity. The pinned runtime seeds EMA with a length-period SMA; this initialization must be checked against the intended TradingView reference. The app deliberately retains **TradingView comparison pending** until evidence is supplied. Fonts and curves can differ between renderers even when numeric outputs match.

## Market Gravity example

The example is the user's original 4,773-line Pine v6 source, with its MPL-2.0 notice and YinYangAlgorithms attribution retained. All 56 input controls are preserved, including liquidity detection, lifecycle, gravity parameters, display, alert thresholds and style. The original source uses previous completed daily/weekly high and low requests, confirmed pivots, ATR, EMA, arrays, lines, labels, polylines and a table. Gravity and inferred liquidity retain their original meaning: relative attraction, not probability or actual resting order-book liquidity.

The model emits the original drawings and the live chart renders them. The source's alert conditions remain in the Pine runtime; they are browser-session indicator events, not server-owned execution or notification rules. No paper or live order is generated by adding Pine source.

## Reference comparison

The report records the SHA-256 fingerprint of the pasted source, runtime version, source-qualified market/timeframe, test timestamp, loaded and completed bar counts, completed cutoff, all input defaults/values, drawing counts, warnings and secondary-feed windows. A frozen test-start timestamp determines which bars are completed. CSV comparison receipts include the reference filename, fingerprint and comparison timestamp. Forming-bar visuals are provisional and excluded from CSV comparison.

Download **Comparison Pine**, **Local output CSV** and **Test report**. For Market Gravity, Comparison Pine appends 13 data-window plots observing the original net gravity, six ranked scores and six target prices; it does not change the installed source. A fixture test verifies that this instrumentation preserves line geometry and styling.

Run Comparison Pine in TradingView on the same venue, symbol, interval, inputs and loaded history; export its chart data and load it through **Compare TradingView CSV**. The CSV must include time and matching open/high/low/close, volume when supplied, and the same output column titles. Timestamps can be ISO or epoch seconds/milliseconds. At least three shared completed bars and finite outputs are required. Different OHLC/volume, duplicate timestamps and missing outputs fail explicitly. Each numeric output uses absolute tolerance `1e-7` plus relative tolerance `1e-8`. Reports include mismatch counts and up to 100 examples. A successful comparison applies only to those shared bars and outputs; visual parity remains unverified.

The initial tests did not use a TradingView reference export. Synthetic fixture self-comparisons test the comparison mechanism; they are not TradingView parity evidence.

## Rebuild and test

```sh
npm ci --ignore-scripts
node build-vendor.mjs
npm run build:pine
npm run test:pine
node --test tests/test_sma.mjs
python3 launch.py --qa --port 18881 --journal-port 3102 --detach
DESK_QA_HTTP=1 QA_JOURNAL_PORT=3102 python3 -m unittest discover -s tests -v
python3 launch.py --qa --stop
```

Vela's installed repository source/dependencies are required by `build-vendor.mjs`; `TRADER_REPO` can specify that repository root. `PINE_BUILD_DIR` can override the installed npm dependency directory for `build-pine.mjs`. The Pine bundle imports the already bundled `vela.js` to keep one chart registry and SDK instance. Existing paper-trading and Lux Journal state stays under ignored runtime directories.
