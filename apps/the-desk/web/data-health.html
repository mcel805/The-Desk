Recovery

Verify checks file hashes, SQLite integrity and retained row counts. Test restore opens a separate restored copy and leaves the live databases untouched.

To replace damaged data, stop The Desk, choose a verified snapshot and install only the affected database. The previous database and its WAL files are preserved in a recovery folder. A restored snapshot contains records through its recorded cutoff; newer records need separate recovery. Account logins must be reconnected.

The offline installer refuses to replace a database while this data directory is open. If corruption is detected at startup, this recovery page remains available and normal collection and trading services stay stopped.
