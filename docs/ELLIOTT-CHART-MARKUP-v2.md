# Rider Elliott chart package v2

Quant Lab's **Give me an Elliott Wave Analysis** action collects six Hyperliquid public reference charts for the trader symbol (Daily, 4h, 1h, 30m, 15m, 5m) plus the active trader chart. The reference views use all bars returned by the provider request: Daily may have fewer than 5,000; the other intervals may hit the 5,000-bar request cap. The Daily completed OHLCV history and each interval's source-bound swing candidate catalog are supplied for the analysis. The catalog identifies exact wick candidates, not confirmed Elliott waves.

The chat reads a fenced `chart-markup` JSON object with schema `cleo.elliott-markup.v2`. `frames` contains seven objects, in Daily-to-5m order followed by the trader view. Each frame declares `workspace`, `chart`, exact `source` identity and cutoff, `degreeStatus` for major/intermediate/minor, a `primary` pivot ledger, an optional alternate, Fibonacci anchors, conditional forecasts, invalidations, optional source-anchored trendlines/channels, and a short readout. The source and cutoff must match the loaded chart at application time.

Every historical pivot and Fibonacci endpoint must cite an exact **completed loaded bar**, and its price must fall inside that bar. Fibonacci high and low must equal the cited wick extremes. The UI computes 38.2%, 50%, and 61.8% retracements from those verified anchors. Forecast legs use a cited completed-bar basis, ratios and increasing bar horizons; the UI computes and labels their future coordinates as conditional paths. No future point is presented as an observed candle.

A forecast basis must run from an earlier bar to a later bar, even for a declining scenario. If one forecast branch fails that check, the renderer discards that branch, keeps separately validated historical labels, Fib guides, and other forecast branches on the view, and reports the rejected branch in the chart audit. A rejected path never counts toward full coverage.

The JSON `wave` field uses the bare symbol (`I`, `ii`, `c`); the declared degree supplies its display parentheses. The renderer accepts the same symbol when a model includes Rider's parentheses, then formats it once. A pivot outside its cited bar is discarded and named in the audit; other individually validated marks can remain visible, but the view stays partial. This prevents one bad anchor from blanking the entire reference chart.

Invalidation lines receive the same per-mark treatment: a boundary on a forming, missing, or out-of-range bar is discarded and reported, while independently validated count/Fib/forecast marks remain. If a view cannot be applied at all, the renderer clears its prior Shammy overlay so an older count is never presented as the current run.

Fib anchors are also checked independently. If either endpoint is not an exact completed wick on that timeframe, all three derived Fib guides are omitted and the reason is shown; separately valid wave and forecast marks can still be displayed as partial research. A lower-timeframe Fib must never borrow an unverified higher-timeframe candle.

Trendlines and channels use a separate `trendlines` / `channels` ledger. Every line endpoint and stated touch cites exact completed wick bars. Two anchors are rendered as a **candidate** line; a line is called **supported** only when a third distinct near-line wick touch is independently checked. A channel draws two neutral dashed rails only when their sourced intervals overlap, they remain in upper/lower order, and their slopes support a parallel fit. Failed or unverified structures are omitted with a chart audit note. Channel and trendline marks describe price structure; they do not establish Elliott counts. The chart does not extend rails beyond sourced anchors unless a separately identified conditional projection is supplied.

If a frame has no usable model-supplied Fib or price structure, Quant Lab may add a clearly named fallback from the loaded completed-bar swing catalog: an observed swing retracement, candidate trendline, or candidate channel. These fallback marks are exact-bar OHLC observations and remain explicitly separate from Elliott pivots, wave invalidations, and forecasts. A fallback never upgrades a count or changes the package's partial/unresolved status.

For each view, coverage is reported separately: labels in older, middle, and recent history; three supported degrees; sourced Fib; and a conditional future path. A missing component makes that view **partial**, not complete. The renderer checks source anchors, basic line geometry, and package shape. It does **not** independently establish Frost–Prechter pattern validity, count degree, or predictive performance; a model's rule-audit prose is still model-assisted. Rider's skill requires a separate hard-rule audit, the strongest supported alternate, and unresolved labels where evidence does not support more detail. Never call a count independently validated based only on successful rendering or exact-bar anchors.

The trader and reference chart marks are native Vela drawings. Each reference card has a Count toggle and a Note button; the trader view has the Shammy marks toggle and a movable findings panel. Saved Shammy analyses retain the returned package and its original cutoff. Restoring one requires the exact loaded snapshot. The small Prechter Figure 2 inset in chat is an attributed textbook model for an identified A–B–C correction; it is never the data evidence or a replacement for chart marks.
